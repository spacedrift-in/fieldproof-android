> Honest, versioned list of known limitations and the verified status of each.
> Entries are appended over time and point at the evidence that confirms or
> mitigates them. **None of these entries weaken the acceptance criteria that
> the demo is synthetic-only and private-data-free** (see
> `acceptance-criteria.md`).

| KL-029 | 2026-10-15 | High | Mitigated | The checklist-outcome sync operation id is deterministic (`checklist:<itemId>`), and acknowledgement was unconditional: an upload that completed **after** a newer local edit marked the item/operation `SYNCED`, leaving the newer edit stuck `QUEUED` (and later re-racing) — the classic interrupted/resumed overwrite race. | **Mitigated 2026-10-15:** each edit bumps `checklist_items.localRevision` (Room migration 3→4) and stamps it on the operation; `ChecklistItemDao.acknowledgeSyncedOutcome` only marks both rows `SYNCED` when a **compare-and-set** on revision still matches, inside a single Room transaction (`claimChecklistUpload` does the same for the `UPLOADING` claim). | KL-030 | 2026-10-15 | High | Mitigated | Photo evidence was persisted with a plaintext fallback: `InspectionRepository.addEvidence` did `evidenceVault.import(uri) ?: localUri`, so an encryption failure (keystore unavailable, unreadable capture, undeletable plaintext) silently stored — and later uploaded — unencrypted bytes. | **Mitigated 2026-10-15:** `EvidenceVault.import` returns a typed `EvidenceImportResult` (`Sealed`/`AlreadySealed`/`Unmanaged`/`Failed`); a `Failed` result aborts the save, so no evidence row or sync operation is created and no plaintext is kept. `EncryptedEvidenceVault` also deletes the temporary plaintext on failure and refuses to keep a sealed copy whose plaintext it could not remove; the UI surfaces a "retake the photo" message instead of silently dropping the capture. | KL-031 | 2026-10-15 | Medium | Mitigated | The Android client hard-coded `http://127.0.0.1:8000/` and the manifest set `usesCleartextTraffic="true"`, so a mis-built release could ship cleartext HTTP and a loopback endpoint. | **Mitigated 2026-10-15:** the base URL is injected at build time as `BuildConfig.API_BASE_URL` (from `FIELD_PROOF_API_BASE_URL` or the `fieldproof.apiBaseUrl` Gradle property); the manifest points at `@xml/network_security_config`, whose **release** variant denies cleartext (`cleartextTrafficPermitted="false"`) while the debug variant allows it for localhost development. | KL-032 | 2026-10-15 | Medium | Mitigated | The in-process rate limiter keyed on the unverified `X-Tenant-Id` header and kept a `dict` of hit counts with no TTL or size bound, so a caller could rotate the header to evade the limit and memory could grow without bound (and each replica enforced its own limit). | **Mitigated 2026-10-15:** the limiter now keys on the client transport address (or a single configured, trusted header such as `X-Real-IP` via `RATE_LIMIT_CLIENT_IP_HEADER`), evicts expired keys on a TTL, and caps total keys (`RATE_LIMIT_MAX_KEYS`, default 10000). Residual caveat: enforcement is per-process; a multi-replica deployment needs a shared limiter (e.g. Redis) or an edge/WAF rate limit. |
| KL-033 | 2026-10-15 | Medium | Mitigated | `update_checklist_outcome` treated any request whose `expected_version` was stale as a 409 conflict, so a client that lost the response and retried the **same** outcome got a false conflict and the item appeared stuck. | **Mitigated 2026-10-15:** the service now distinguishes an idempotent replay from a genuinely different later edit — if the item already matches the incoming `status`/`note`, it returns the current item without bumping the version or raising a conflict; only a stale version with a *different* value still 409s. ## Synthetic-data guarantee

Every fixture, screenshot, log and PDF in this repository is synthetic and
contains no secrets, credentials, or private client data. This is enforced by:

- fixtures living only under `tests/fixtures/` and `backend/app/demo_data.py`;
- the evidence photo being a generated placeholder
  (`scripts/seed_demo.py :: make_synthetic_photo`);
- `.gitignore` excluding `.env`, `local.properties`, `.venv/`,
  `backend/var/`, `__pycache__`.

If a reviewer finds anything real, it is a bug — please report it and the
offending file will be scrubbed.
